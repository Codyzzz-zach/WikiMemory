WGEMemory4LLM · Product Definition v1.5

让 Agent 的多领域认知随使用持续进化

这不是一个给人浏览的 AI Wiki，也不是把更多文件塞进上下文的检索工具。WGEMemory4LLM 是外挂于通用 Agent 的自治知识编译与长期记忆层：它把不断到来的材料、对话、纠正与任务结果，转化为可验证、可演化、可被任务直接消费的知识状态。

产品定义：WGEMemory4LLM 持续把人类的多领域知识资产编译为可版本化、可追溯、可纠正的知识状态；在任务发生时，以检索入口、受审计的局部 Graph 导航和证据闭包生成有预算的 Context Pack，使通用 Agent 能跨文档、跨语言、跨会话积累并正确更新认知。

01 / Goal

先定义目标，再允许架构存在

产品的北极星不是“Wiki 写得多”“Graph 边很多”或“编译准确率高”，而是：同一个 Agent 在持续吸收多领域材料后，能否比第一天更少要求用户重复解释、更少复发已纠正错误，并在跨材料、跨语言和跨时间任务中给出更完整、更有依据的判断。

flowchart LR A["新材料与真实任务"] --> B["编译知识状态"] B --> C["任务化 Context Pack"] C --> D["Agent 回答与行动"] D --> E["纠正与任务结果"] E --> B B --> F["认知更完整且更少过期"]
Ultimate outcome

持续改善任务结果

系统最终为 Agent 的回答、判断与任务结果负责；Wiki、Graph、Claim 与 Lint 都只是实现该结果的机制。

Compounding effect

知识发生变化，而非文件堆积

新证据进入后，旧认识会被增强、削弱、分叉、加条件或标记过期；后续任务使用的是“当前知识状态”。

Trust boundary

进化不能以失真换取

任何进入回答的结论，都能回到来源、适用条件、生成版本与演化历史；不确定性不得被静默抹平。

目标公式：有效进化 = 新证据带来的认知修正 × 后续任务中的正确复用 × 可追溯与可回滚；如果只增加材料数量而任务质量没有改善，不算进化。
01A / Operating Contract

产品只有一条在线链路，消融组不是产品模式

历史 P-seed、P-graph 与 E-min 只用于拆解组件贡献，不应演变成用户必须理解的产品模式。类型化 Relation 与邻接索引是长期治理、冲突、替代、依赖和影响传播的必要知识状态；在线读取链必须 Graph-capable，但不是 Graph-always-on。Seed 先定位入口，只有关系意图、安全风险、版本/影响任务或可观测覆盖缺口触发时，受审计 Graph 才进入有界候选导航；最终只把任务必要的 Claim、条件、来源和 Evidence 送给 Agent。

或覆盖缺口触发?"} T -->|"否"| R0["有界 Seed 候选"] T -->|"是"| C["受审计候选 Graph"] C --> R["结构排序与风险检查"] R0 --> V{"可见内容门禁"} R --> V V --> P["Claim 条件 Provenance Evidence"] V -->|"关系意图 安全边 覆盖缺口"| G["最小必要关系路径"] P --> A["Agent 回答"] G --> A A --> F["结果 纠正 Evolution"]
Governance

离线 Graph 始终存在

用于冲突、替代、依赖、影响分析、Lint 和 Evolution；在线是否展示关系不影响其治理价值。

Navigation

候选 Graph 条件参与

只有触发条件成立，且边满足当前审计版本、端点闭合、条件明确和 scope/knowledge-time 约束时，Graph 才参与局部结构排序。Graph 不能制造 Seed。

Visible context

关系内容条件触发

查询明确要求路径、关系会改变答案安全性，或 Seed 存在可观测缺口时，才输出最小必要路径；其余边留在内部。

复杂度纪律：“Graph 是长期知识基础设施”不等于“每个查询都必须遍历 Graph”，更不等于“Graph 内容默认追加”。候选子图与可见 Context 子图必须分离；具体触发、排序、路径和渲染继续按答案质量、hard failure、总 token、工具调用、延迟和规模收益验收。执行细则见 WGEMemory4LLM-Iteration-Operating-Plan.md。
02 / Problem

原始问题：知识更新快，但 Agent 每次都像第一次来

个人学习

AI 行业、技术与产品实践更新快、材料多。用户需要 Agent 共同消化文章，形成跨文章的支持、冲突、补充与演化视野，而不是每次围绕一篇文章做孤立摘要。

长期项目与业务

项目持续产生背景、决策、复盘与纠正。团队需要一个懂业务、能持续跟进的 Agent；但 MVP 暂不解决多人权限与组织治理，仅保留未来扩展边界。

flowchart TD S["材料快速增加"] --> P["信息散落在文件与对话"] P --> R["每次任务重新检索与解释"] R --> L["跨材料关系被临时发现后丢失"] L --> E["Agent 不会随使用稳定进步"] E --> S

现有替代方案为什么不够

替代方案能做好什么无法稳定解决什么
普通文件夹 + grep/BM25定位关键词与已知答案不能把多次临时发现的关系沉淀为长期依赖，也不知道新证据影响哪些旧结论。
向量 RAG按语义召回局部片段召回相似不等于恢复支持、冲突、条件、版本与多跳关系；更新通常只增加切片。
全量上下文小语料时保留最多原文成本随材料增长；任务相关性、过期观点和冲突处理仍依赖每次临时推理。
人工 Wiki产生稳定、可寻址的知识页面用户没有时间持续维护；知识更新速度高于人工策展能力。
对话 Memory保存偏好与历史互动若缺少证据、条件和版本治理，容易把推断与事实混在一起并长期放大错误。
替代方案死亡测试：如果“文件夹 + Coding Agent”已经能在相同上下文预算内稳定恢复跨材料关系、正确处理条件与过期结论，并让已纠正错误不再复发，WGEMemory4LLM 就没有独立存在价值。
03 / Scope

产品边界：Agent-first，不是 Wiki-reader-first

flowchart LR U["人类用户"] -->|"提问 学习 纠正"| A["通用 Agent"] A -->|"任务描述"| W["WGEMemory4LLM"] W -->|"Context Pack 与证据路径"| A S["文章 对话 反馈 任务结果"] --> W W --> G["Git 管理的知识状态"]

MVP 明确包含

  • 单用户、多领域的长期知识状态；覆盖科技、AI、金融、历史、数学、人文、心理、健康、生物、设计等混合资产，不用单一领域定义通用架构。
  • 材料自动摄入、知识编译、Wiki 模块维护、类型化 Graph、Evidence 回链、写入时 Lint、周期性语义 Lint。
  • 任务发生时生成任务子图与 Context Pack，供任意兼容 Agent 消费。
  • 用户可通过自然语言纠正；不要求用户编辑 Wiki 或逐条审批 AI 写入。
  • Git diff、编译 manifest、依赖追踪、局部重编译与回滚。

MVP 明确不包含

  • 多人协作权限、组织级事实责任人、审批流和合规审计。
  • 以人类浏览量、页面编辑量或知识图可视化停留时长作为核心价值。
  • 把全世界知识建成通用知识图，或承诺 Graph 自身能够保证多跳推理正确。
  • 替代原始材料；原文是不可变证据，编译结果始终可被丢弃并重建。
  • 把主题 domain 当作权限边界；权限与适用范围由 GLOBAL/PERSONAL/PROJECT scope 决定，domain 仅作检索、组织和评估提示。
  • 固定依赖某个模型、向量数据库或图数据库。模型可替换，输入输出合同不可含糊。
角色区分：用户是受益者与纠正者；通用 Agent 是首要消费者；Ingestor、Compiler/Librarian、Linter 是系统内部职责，而不是要求用户扮演的人工岗位。
04 / Philosophy

设计哲学：遵守它们，产品才会持续朝目标推进

每条哲学都从目标反推，给出必须做什么、拒绝什么，以及怎样验证。它们高于具体技术方案：当模型、存储或检索实现变化时，哲学仍然约束产品方向。

flowchart TD G["目标：Agent 随使用持续改善"] --> P1["Agent 效果优先"] G --> P2["演化优先于堆积"] G --> P3["证据与可逆性"] P1 --> P4["任务化上下文"] P2 --> P5["类型化且带条件的关系"] P2 --> P6["自治写入与分级发布"] P3 --> P7["语义 CI 与依赖重编译"] P4 --> P8["复杂度必须被增益证明"]
Philosophy 01

为 Agent 的任务结果优化，而不是为知识资产的外观优化

Agent 要在真实任务中变好
→
Wiki 与 Graph 只是中间资产
→
所有功能都接受下游效果检验

必须：以回答完整性、纠错复发、条件处理、任务偏好与用户继续学习意愿评估价值。拒绝：用节点数、边数、页面长度或“看起来像知识库”替代用户结果。

守门问题：如果删除这个组件，Agent 的任务表现是否稳定下降？如果没有证据，该组件不能成为架构前提。

Philosophy 02

积累的单位是“可修正的知识状态”，不是文件与摘要

新材料不断进入
→
旧认识必须被重新判断
→
后续任务只消费当前有效状态

必须：识别支持、冲突、补充、取代和适用条件；新文章可能修改多个既有 Wiki 模块，而非机械新增一篇摘要。拒绝：只追加切片、只按来源建页面、只用“更新时间”假装知识已经演化。

验收：摄入纠错材料后，系统能找到受影响的 Claim、Relation 和 WikiModule，局部重编译，并在新回答中停止复发旧错误。

Philosophy 03

原文是不可变证据；Wiki 与 Graph 是可丢弃、可重编译的观点

AI 编译必然会错
→
派生知识不能冒充来源
→
每个结论都能回链并重建

必须：SourceSpan、内容哈希、来源版本、编译器版本和引用链完整保存；Git 记录派生状态的变化。拒绝：把摘要覆盖原文、把无来源推断直接写成事实、用 Git 回滚能力替代正确性校验。

验收：从任一回答中的关键结论，最多两次跳转可到原文片段；删除全部派生文件后可从原文重新生成。

Philosophy 04

AI 拥有完整写入权，但不拥有无条件成为 Canonical 的权力

人不会持续维护
→
AI 必须自治写入
→
发布状态与认识状态必须分层

必须：所有生成物自动保存；通过结构与证据 Lint 后才进入 Canonical 消费链。UNRESOLVED、DISPUTED、SUPERSEDED 与 QUARANTINED 都可保留，但 Agent 的默认使用规则不同。拒绝：要求人逐条审批，也拒绝”先全部当真、月底再统一纠错”。

验收：低质量或无证据内容可以被记录和诊断，却不会污染默认检索、Graph 扩展与 Context Pack。

Philosophy 05

关系必须类型化、带条件、带方向；“相关”不能冒充推理依据

多跳价值来自关系
→
压扁关系会稳定传播错误
→
Graph 边也必须接受证据治理

必须：区分 REQUIRES、DERIVED_FROM、SUPPORTS、CONTRADICTS、SUPERSEDES、EQUIVALENT_UNDER 等；边携带适用条件、证据、时态和状态。拒绝：把“有限测度空间下 L²⊆L¹”压成无条件 IS_A，也拒绝强行注入不存在的 counter 来制造“多路证据”。

验收：Graph 可以回答“为什么连”“在什么条件下连”“谁支持这条边”“它变化后影响谁”；RELATED_TO 只能导航，不能直接支撑结论。

Philosophy 06

提前编译可复用结构，延后生成任务特定答案

纯查询时推理没有复利
→
过度预编译产生无关推断
→
编译层与运行时各司其职

摄入时：保存原文、Claim、稳定 Concept、跨材料关系候选、Wiki 模块增量和依赖。任务时：理解意图、选择任务子图、回填必要原文、组织 Context Pack、生成答案。拒绝：摄入时穷举未来问题，也拒绝每次任务都从零发现已知关系。

验收：相似任务可以复用既有模块与关系；不同任务仍能获得不同的 Context Pack，而不是同一份“大而全”摘要。

Philosophy 07

全局视野是一张可导航的知识地图，不是把整个 Wiki 塞进上下文

材料规模持续增长
→
上下文预算永远有限
→
先地图、后子图、再证据

必须：先让 Agent 获得主题、冲突、最近变化和关键路径，再按任务加载 WikiModule 与 SourceSpan。拒绝：用更大上下文窗口掩盖选择问题，或让 Graph 路径无限扩张。

验收：Context Pack 有明确预算、选择理由、路径深度、去重规则和丢弃日志；重要的冲突与条件优先于重复背景。

Philosophy 08

模型可以是黑盒，但产品责任必须白盒

底层模型会更换
→
能力波动不可避免
→
IO 合同、权限与失败处置必须稳定

必须：定义每阶段输入输出 schema、上下文边界、工具权限、超时、重试、幂等、降级、隔离与回滚。拒绝：用“LLM 会理解”替代数据合同，用 prompt 约定替代消费链路隔离。

验收：更换模型后，系统仍能运行结构 Lint、证据回链、版本 diff 和回归集；能力下降能被观测而非静默发生。

Philosophy 09

语义 CI 必须发生在消费前，并能沿依赖传播

错误进入记忆后会被反复消费
→
定期检查太晚
→
写入时门禁 + 周期性全局 Lint

写入时：检查 schema、引用存在、证据支持、条件、状态和孤儿依赖。周期性：检查跨模块冲突、重复、过期、循环依赖、孤立推断与回归问题。拒绝：failed 内容留在默认 Graph 中再在答案拼装阶段过滤。

验收：Quarantine 与 Canonical 在物理或索引层隔离；任何默认消费路径都不能先被失败节点影响排名、再晚过滤。

Philosophy 10

复杂度必须通过对照实验赢得存在权

Graph 与 Compiler 成本高
→
概念正确不等于产品有效
→
每层都设置消融与死亡标准

必须：与强原文检索、Seed-only、Graph-aware ranking、Wiki-assisted 做同预算与自然成本对照；分别评估直接事实、多跳、条件、冲突、跨语言与增量更新。拒绝：因为“Graph 理论上适合多跳”就把遍历内容默认追加到 Prompt。

验收：Graph 长期保留为治理与候选排序层；可见关系路径必须通过独立消融赢得 token。若结构排序暂时没有稳定增益，回到边质量、ranking、gate、规模或成本诊断，收窄可见内容，但不退回无 Graph 的长期架构。

05 / Knowledge Model

WGE：语义、拓扑与可信度三层共同构成 Memory

Wiki · 物化派生视图

完整语义

围绕稳定主题、概念或长期问题组织的可寻址模块。它吸收多份来源，给 Agent 连贯解释，不等于某篇输入文章的摘要。认识论上是派生视图（可丢弃、可重编译），工程上持久化、版本化、增量更新——内容可积累结构与表达质量，但知识权威不可独立积累。

Graph

关系、治理与候选导航

保存概念、Claim 和模块之间的类型化、条件化、可追溯关系。离线用于冲突、影响和增量重编译；在线默认只在有界候选池中参与排序，只有最小必要路径进入 Context。

Evidence

事实锚点

不可变原文及定位信息。它回答“作者究竟说了什么”，约束 Wiki 与 Graph 不能独立成为没有出处的真理。

flowchart TD E["Evidence：原文片段"] --> C["Claim：最小可判断结论"] C --> K["Concept：稳定概念身份"] C --> R["Relation：类型 条件 方向"] K --> W["WikiModule：长期语义模块"] R --> W W --> P["Context Pack：任务投影"] R --> N["Graph-aware 候选排序"] N --> P E --> P

最小一等对象

对象职责必须字段不得承担
Source / SourceSpan保存不可变证据及精确定位hash、URI/path、版本、位置、原文不保存 AI 改写后的“更正确原文”
Claim最小可判断结论陈述、来源、条件、时态、认识状态不把整篇摘要当一个 Claim
Concept跨来源稳定身份与别名ID、名称、别名、边界、领域不承载长篇解释
Relation连接 Claim/Concept/Module类型、方向、条件、证据、状态、版本RELATED_TO 不可直接当推理证据
WikiModule供 Agent 阅读的完整语义单元（物化派生视图）稳定地址、核心问题、当前认识、争议、引用、依赖不按输入文件一一生成；内容可积累但知识权威不可独立积累——每个断言必须由 Canonical Claim/Relation 支撑，不得成为 Claim 的反向证据来源
ContextPack面向当前任务的运行时投影任务、地图、子图、模块、证据、预算、选择解释不成为长期知识的唯一存储

四个正交状态轴（v1.1 修正）

v1.0 把”怎么来的””是否有争议””是否过期”混进单一 epistemicStatus，无法表达”AI 推导的、存在争议、尚未被取代”这种组合。v1.1 拆成四个正交轴。

争议性validitySUPPORTED DISPUTED UNRESOLVED当前是否有充分支持或存在争议。新 Claim 初始 UNRESOLVED（待证明），门禁通过才 SUPPORTED。
时态lifecycleACTIVE SUPERSEDED是否仍然有效。SUPERSEDED 保留历史但不进入默认消费。
发布publicationStateCANDIDATE CANONICAL QUARANTINED是否进入默认消费链。QUARANTINED 必须物理隔离（独立存储），不仅是状态标记。
消费按顺序判断，不建 54 格查表
  1. 不是 CANONICAL → 不消费
  2. 已 SUPERSEDED → 默认不消费（历史/asOf 查询除外）
  3. SUPPORTED → 可以正常使用
  4. DISPUTED → 只能作为争议呈现（conflictsAndConditions）
  5. UNRESOLVED → 不能当作确定事实（knownGaps / 导航）

状态分类

类别含义示例
稳定状态可以长期持久化EXTRACTED + SUPPORTED + ACTIVE + CANONICAL
过渡状态门禁处理中可能短暂存在SUPPORTED + CANDIDATE（已获证据支持但等待发布门禁）
历史状态不再消费，但必须保留DISPUTED + SUPERSEDED + CANONICAL（先争议后取代的完整演化路径）
非法状态违反状态语义，写入时应拒绝CANDIDATE + SUPERSEDED（从未发布的 Candidate 不应叫”被取代”）

时间语义（v1.4 起：knowledge time + 显式版本取代）

MVP 完整支持“系统何时知道这件事”（knowledgeVersion / recordedAt / knowledgeAsOf），并支持由来源明确表达、经 SUPERSEDES 或版本元数据确认的“当前版本 vs 历史版本”。MVP 不承诺通用的现实世界有效时间区间查询；任意 validAt 双时态推理仍推迟到 Post-MVP。

概念MVP 支持含义
knowledgeVersion✅知识状态的版本标识
recordedAt✅系统记录这条知识的时间
knowledgeAsOf✅重建系统在某个版本/时间点已记录并认可的知识状态
显式版本 / SUPERSEDES✅ 有限支持回答当前版本时优先 ACTIVE；按明确版本或历史知识快照保留旧对象
validAt（现实有效时间）Post-MVP"某个事实在现实中从何时到何时成立"——MVP 不回答

材料中明确出现的时间条件（如“2020 年之后的方法”）必须保留在 Claim 文本或 conditions 中；只有明确版本、来源时间和受审计 SUPERSEDES 能驱动当前/历史选择。validFrom/validTo 字段继续保留，但不得被解释为已经实现任意现实时间区间推理。

Relation 端点规则（v1.1） Candidate Relation 可以引用同一编译批次中的 Candidate Claim 或既有 Canonical Claim；发布时，其端点必须在结果快照中全部成为 Canonical。任一端点在门禁中失败（QUARANTINED）时，依赖该端点的 Relation 不得单独发布。跨材料检测产出的 Relation，端点检查范围为全局 Canonical 集合（非同批次）。
CANDIDATE 与 QUARANTINED 的边界（v1.1）
  • CANDIDATE：结构有效、可安全继续评估、但尚未完成证据或发布门禁的对象。单纯证据不足应保持 UNRESOLVED + CANDIDATE，不应自动隔离。
  • QUARANTINED：触发硬失败、不能进入默认消费路径的对象——结构损坏、引用不存在、状态造假或无法安全继续处理。

Claim 的语义元数据：claimKind 与 scope（v1.1 新增）

claimKind 和 scope 是 Claim 的语义元数据，不是第五、第六个状态轴——它们不参与”是否消费”的判断，只参与”在哪里生效”和”谁是权威”。

字段值含义
claimKindFACT | DECISION | PREFERENCE决定用户能否成为该 Claim 的权威
scope.typeGLOBAL | PERSONAL | PROJECT决定 Claim 在哪里生效
scope.idstring（可选）项目/作用域标识
关键不变量 scope 决定一条 Claim 在哪里生效；claimKind 决定用户能否成为该 Claim 的权威。项目作用域本身不会把事实变成用户可直接确立的决策。项目范围内的事实（如”复现失败”）仍需实验记录或来源支持。scope 不决定发布状态，但决定 Claim 对当前任务是否适用、能否被选入 Context Pack。

作用域消费链（v1.1：Global Base + Scoped Overlay）

加入 scope 后，Wiki 编译和 Context Pack 选择都必须作用域感知，否则”项目 A 选 MoCo、项目 B 选 SimSiam 合法共存”无法在消费层落地。

Wiki 层说明
Global Base所有用户共享的世界事实 Wiki（如”MoCo 是对比学习方法”）
PERSONAL Overlay当前用户的个人偏好（稀疏叠加，不为每用户复制完整 Wiki）
PROJECT Overlay特定项目的决策（稀疏叠加）
interface ScopeContext { principalId: string // 当前用户 projectId?: string // 当前项目（可选） }

Context Pack 作用域选择规则（缺少 ScopeContext 时按 Global-only 处理，不能”默认全选”）：

  1. 始终包含匹配的 GLOBAL 知识
  2. 包含当前 principalId 的 PERSONAL 知识
  3. 有 projectId 时，只包含该项目的 PROJECT 知识
  4. 绝不召回其他个人或项目作用域的知识
Overlay 约束 Scoped Overlay 是适用性叠加，不是对 Global 事实的无条件覆盖。项目决策可以替代同一项目内的旧决策；项目范围内的 FACT 仍不能凭作用域权威覆盖世界事实。

SUPPORTED 在不同通道中的含义

claimKindSUPPORTED 的含义依据类型
FACT命题受到材料或实验记录支持SourceSpan / 实验记录
DECISION该作用域内确实存在一项有效的权威决定AssertedRecord（权限 + 作用域校验）
PREFERENCE该主体确实声明了当前偏好AssertedRecord（主体声明）

证据引用拆分：provenance 与 supporting evidence（v1.1）

Claim 的引用分为两层，防止"用户说过"被误判为"命题已被证明"：

引用类型含义KnowledgeRef 子类型
provenanceRefs证明"谁在何时提出了这个说法"——不证明它对不对AssertedRecordRef
supportingEvidenceRefs证明"命题本身为真"——原文片段、实验记录SourceSpanRef, ExperimentRecordRef, AssertedRecordRef（仅 DECISION/PREFERENCE）
Claim 类型AssertedRecord 的角色
FACT只能作为 provenance（"用户说过"），不能单独进入 supporting evidence
DECISION经作用域和权限校验后，可同时作为 provenance 和 supporting evidence
PREFERENCE经主体校验后，可同时作为 provenance 和 supporting evidence
最危险的错误 把"用户说过"误判成"命题已被证明"。事实纠正有 provenance 但暂时没有足够 support；只有授权的 DECISION/PREFERENCE 才能让 AssertedRecord 本身作为支持依据。rationale 引用的实验或材料仍需作为独立 supporting evidence 接受审计。

AssertedRecord 最小合同

{ “assertionId”: “assert:...”, “claimId”: “claim:...”, “assertedBy”: “user:alice”, “assertedAt”: “2026-07-23T...”, “scope”: { “type”: “PROJECT”, “id”: “proj-vision” }, “authorityBasis”: “role:tech-lead”, “assertionText”: “我们项目决定使用 MoCo 而非 SimSiam”, “rationale”: “MoCo 在小 batch 下更稳定（可选）”, “supportingSourceIds”: [“source:experiment-log-...”] }

硬门槛字段（缺一不可发布）：assertedBy, assertedAt, scope, authorityBasis, assertionText。推荐字段：rationale（项目决策强烈推荐，个人偏好不强制）。缺失 rationale 仍可发布，但标记“理由未记录”。

统一原则 所有 SUPPORTED Claim 都必须有可审计的依据；事实的依据是 SourceSpan 或实验记录，决策与偏好的依据是经过权限和作用域校验的 AssertedRecord。Rationale 解释”为什么”，但不普遍决定该断言”是否成立”。

HUMAN_ASSERTED 纠正的非对称规则

场景状态处理
用户用未经验证的新说法纠正既有事实旧 Claim → DISPUTED；新 Claim → HUMAN_ASSERTED + UNRESOLVED + CANDIDATE，建 CONTRADICTS
两条没有外部支持的用户断言互相矛盾两者都保持 UNRESOLVED，记录 CONTRADICTS（不够格成为”有证据的争议双方”）
两条都有独立支持的 Claim 相互冲突两者都可以是 DISPUTED
用户修改自己的偏好或项目决策同主体同作用域：新决策 SUPERSEDES 旧决策

非对称原则：用户的纠正足以让系统立即停止无条件相信旧结论，但不足以自动证明用户的新结论为真。

Relation 最小合同（v1.1 修正）

{ “id”: “rel:...”, “from”: “claim:...”, “to”: “claim:...”, “type”: “REQUIRES | DERIVED_FROM | SUPPORTS | CONTRADICTS | SUPERSEDES | EQUIVALENT_UNDER | RELATED_TO”, “conditions”: [“适用空间、时间、假设或定义域”], “evidenceSpanIds”: [“span:...”], “derivation”: “EXTRACTED | INFERRED | HUMAN_ASSERTED”, “validity”: “SUPPORTED | DISPUTED | UNRESOLVED”, “lifecycle”: “ACTIVE | SUPERSEDED”, “publicationState”: “CANDIDATE | CANONICAL | QUARANTINED”, “validFrom”: null, “validTo”: null, “compilerVersion”: “...”, “source”: “intra-material-compile | cross-material-detect | human-confirm | periodic-lint”, “consumedBy”: [“wiki:...”], “confidence”: 0.0 }

v1.1 删除了 direction 字段——方向语义完全由 type 决定（每种 RelationType 在 RELATION_TYPE_SEMANTICS 表中定义 symmetric / allowReverseNavigation / allowReverseReasoning / canSupportConclusion）。from/to 确定实例端点顺序，不需要额外字段。增加了 source 字段区分同材料编译 vs 跨材料检测产生的边。

规范源声明（v1.5） Product Definition 定义产品级不变量；Relation 对象语义由 docs/specs/knowledge-contract.md 定义，当前可执行语义表在 src/graph/index.ts。architecture-baseline.html 只定义模块边界与治理原则，不复制完整端点表。产品级不变量：direction 字段禁止存在；方向由 type + from/to 唯一定义；对称类型由语义表声明；未知 Relation 类型属于硬失败；Linter 必须按语义表验证端点。

三条核心信息流：摄入、问答、进化

流 1：新材料进入后，不是“多一篇摘要”，而是“当前知识状态发生 diff”

v1.1 摄入生命周期（两阶段原子提交）

一次完整摄入包含两个独立原子阶段：

  1. 阶段 1：单材料编译 → Claim/Relation 门禁 → 发布 Canonical Claim（原子）
  2. 阶段 2：基于 Concept+关键词召回相关旧知识 → 增量跨材料 Relation 检测 → Relation 门禁 → 发布（原子）

阶段 2 失败不回滚阶段 1 的 Claim；ingest 返回 PARTIAL + RELATION_SCAN_PENDING，等待重试或周期回填。两阶段都完成才报 COMPLETED。另有 relations backfill 命令用于手动/周期补漏。MVP 不依赖 embedding（向量召回是否加入由实验决定）。

流 2：Agent 先获得知识地图，再按任务加载子图与证据

非功能约束

可靠性

  • 摄入与重编译幂等
  • 部分失败可恢复
  • 索引可从 Canonical 重建
  • Quarantine 与主链隔离

可审计

  • 每个派生对象有生成版本
  • 关键答案有证据路径
  • 每次选择有 run manifest
  • 回滚不丢失原始材料

可替换

  • 模型通过稳定 schema 接入
  • Graph 可先用 JSONL/邻接索引
  • 向量检索是可选能力
  • Agent 通过统一 Context Pack 消费

成本

  • 增量编译优先于全库重写
  • 上下文有硬预算
  • 低价值关系不进入深层推理
  • 离线 Lint 与在线任务解耦
09 / Success

成功标准：先禁止明显失败，再证明相对增益

三个不可接受的硬失败

Hard fail 01

无依据断言

答案把无来源或证据不足的推断包装成确定事实。

Hard fail 02

纠正后复发

系统已经收到并发布纠正，但后续同类任务仍默认复用旧错误。

Hard fail 03

静默抹平冲突

知识状态已知存在冲突或适用条件，答案却输出单一无条件结论。

分层衡量

层级问题候选指标它不能替代什么
编译质量材料是否被忠实编译？证据覆盖、Claim 支持度、条件保留、Relation 精度不能替代真实任务效果。
检索与组装任务是否拿到正确知识？路径完整度、关键 Claim 召回、无关上下文率、预算利用不能替代答案是否正确使用知识。
任务结果Agent 是否真正变好？成对偏好、事实正确、冲突处理、解释复用、人工查证次数这是最终产品责任。
演化能力新证据是否改变后续行为？影响发现率、漏改率、纠错复发率、局部重编译范围、回归通过率不能只看 Git 提交数量。
量化立场：目前不伪造一个“提升 30%”的产品结论。Benchmark 会预注册架构假设和死亡标准；真实用户价值先用同模型、同预算的盲测、硬失败和长期纠错复发观察建立证据，再决定是否设商业化 KPI。
10 / Risks & Decisions

主要风险、控制方式与仍待实验回答的问题

风险为什么危险产品控制验证方式
错误复利一次错误编译会被后续 Wiki、Graph 和答案反复消费。四正交状态轴、消费前门禁、证据回链、Quarantine、回归问题。注入已知错误与纠错材料，观察是否传播与复发。
Graph 过度确定条件被压扁成边后，比文本错误更稳定。条件字段、弱边禁推理、跨来源证据、Relation Lint。L²/L¹、一致收敛等条件陷阱题。
知识模块膨胀Wiki 越来越长，运行时仍然无法选择。稳定问题粒度、模块拆分规则、任务子图、上下文预算。规模增长实验与无关上下文率。
模型自证循环同一个模型生成、审核、回答，可能共同接受同一错误。原文锚点、规则 Lint、独立提示/模型裁判、人工抽样盲评。多裁判一致性与人工仲裁。
回滚伪安全Git 能回退文件，却不知道哪个版本正确。健康标签、语义 CI、benchmark 回归、发布 manifest。故障注入后恢复到最近健康版本。
技术复杂度自嗨Graph 的具体边类型、ranking、可见路径，及命题化、Wiki、Board 的实现都可能没有真实增益。B/R0/R1/W 分层消融、过程 trace、规模/时间曲线、总成本前沿和死亡标准。Graph 治理公理不由单次问答取消；具体实现必须持续被证据约束。

已冻结决策

  • 首要消费者是通用 Agent，人类不负责浏览和维护 Wiki。
  • 核心结果是 Agent 使用效果；编译质量是必要中间指标。
  • AI 可自动写入全部候选，但必须通过基础 Lint 才进入 Canonical。
  • Wiki、Typed Graph、Evidence 三层并存；Graph 不等于自动正确推理。治理 Graph 始终保留，候选导航与可见内容分开验收。
  • 类型化 Relation 与邻接索引是长期治理和影响传播的必要层；在线读取链必须 Graph-capable，但 Graph 是否参与某次排序由任务触发和实验门槛决定。
  • MVP 是单用户、多领域；scope 管权限与适用范围，domain 只作主题提示。
  • MVP 当前只承诺 Markdown adapter，承诺的是可替换 Loader 合同而非一次实现所有格式。
  • Git 提供版本与回滚，语义 CI 提供正确性门禁；二者不可互相替代。
  • 产品面向人类泛化知识资产与通用 Agent；任何单一领域只可作为诊断切片，不能定义架构。

由实验决定、当前不应拍脑袋冻结

  • Graph 结构排序在什么查询、规模和更新周期下开始显现边际收益；哪些触发和最小关系路径值得进入可见 Context。
  • WikiModule 的最佳粒度、候选图上限和 Context Pack 的预算分配。
  • Canonical 自动晋级阈值，以及是否需要异构模型做关键关系复核。
  • 向量检索在个人规模下是否提供足够增益；它不是默认必需组件。
停止方向的信号：在同模型、同预算下，如果 WGEMemory4LLM 不能减少已纠正错误复发、不能更好处理跨材料关系和条件、也不能减少重复解释，那么“可演化知识层”的产品假设不成立，应回退为轻量文件组织或 Agent Skill，而不是继续堆叠架构。
11 / Glossary

统一术语，防止三份文档口径漂移

术语定义
WGEMemory4LLM面向通用 Agent 的自治知识编译与长期记忆层；由 Wiki、Graph、Evidence 共同构成可演化知识状态。
Knowledge State某一时间点上可被 Agent 消费的 Canonical Wiki、关系、状态与证据集合。
Knowledge Evolution新证据导致已有 Claim/Relation/Module 被增强、削弱、加条件、分叉、取代或隔离，并改变后续任务行为。
Semantic Lint / Semantic CI对证据支持、冲突、条件、时态、依赖、过期和回归问题进行的自动检查；不仅检查格式。
Context Pack知识状态针对某个任务、在明确预算内生成的运行时投影，包含地图、子图、Wiki 解释、证据与风险。
Task Subgraph从任务种子概念出发、按关系类型和深度筛选出的局部 Graph；不是全图复制。
Canonical通过当前基础门禁、允许进入默认消费链的发布状态；不等于永恒真理。
Quarantine保留但不进入默认消费链的候选资产，附带失败原因与修复路径。
Compounding已付出的理解成本在后续任务中被复用并减少重复劳动，而不是仅增加存储量。
