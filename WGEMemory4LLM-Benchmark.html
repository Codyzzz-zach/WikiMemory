WGEMemory4LLM · Benchmark v1.0

如何用实验说明它真的有用

Benchmark 不负责证明“Graph 是好技术”，也不把编译准确率包装成产品成功。它要分别回答两个问题：WGEMemory4LLM 是否让 Agent 在真实跨材料任务中优于文件夹搜索；Typed Graph 是否在 Wiki 已经存在时仍提供可重复的额外增益。

核心原则：同模型、同提示合同、同工具预算、同知识版本，逐层消融 Wiki、链接、类型化 Graph 与证据回填；题集在系统构建前冻结，输出盲评，纠错材料按时间注入。只有当后续任务行为真实改善，才能称为“知识进化”。

01 / Claims

先拆开产品命题、架构命题与安全命题

flowchart TD P["产品命题：E 是否优于文件夹搜索 B"] --> U["真实任务更完整 更少复发错误"] A["架构命题：E 是否优于 Wiki-only C"] --> G["Graph 对多跳 条件 更新有额外增益"] S["安全命题：自治写入是否可控"] --> H["硬失败不增加 且可回滚"] U --> D["决定产品方向"] G --> D H --> D
Primary

H1 · 产品价值

在相同模型、相同最终上下文预算与相同原始语料下，Typed Graph + Wiki + Evidence 回填（E）在多跳、条件、冲突和全局结构题上的任务质量，稳定优于文件夹 + Agent 搜索（B），且无依据断言不增加。

Primary

H2 · 演化价值

在注入纠错材料后，E 能正确识别受影响知识、局部重编译并在后续问题中停止复发旧错误；B 需要在每次任务中重新发现纠正，或更容易漏用。

Secondary

H3 · Typed Graph 的独立增益

相对 Wiki-only（C）和无类型双向链接（D），E 在三跳以上路径完整度、条件保留、冲突发现与更新影响分析上更好；单文档直接题不明显退化。

Secondary

H4 · 编译没有以压缩换失真

相对全量原文上下文的信息上限组（A），E 在单跳和事实题上基本持平，在成本标准化轨道中使用更少上下文完成更复杂任务。

Safety gate

H5 · 自治知识状态不放大硬失败

E 不得增加三类失败：无依据断言、已纠正错误复发、已知冲突被静默压成单一确定答案。任何一项明显恶化，都优先否决“效果提升”。

证据阶梯

等级能证明什么本轮是否覆盖
L0 · 结构正确schema、引用、边和 Git 版本能工作覆盖，但不能宣称产品有用。
L1 · 编译忠实Claim、条件与关系来自原文覆盖，是进入任务实验的门槛。
L2 · 离线任务增益在冻结题集上优于基线本 Benchmark 的主证据。
L3 · 纵向进化新证据改变后续行为并停止错误复发通过分批摄入与纠错注入覆盖。
L4 · 真实长期用户价值真实学习质量、重复解释和查证成本持续改善需后续 30 天真实使用，不由数学离线集单独证明。
02 / Corpus & Gold

为什么这 20 篇数学材料适合做第一轮实验

语料表面按 1–20 章线性排列，真实知识拓扑却跨越分析、代数、几何、概率、逻辑与计算。它同时包含显式跨章引用、隐含依赖链和若干“缺少条件就会错”的表述，因此可以把“搜到局部答案”与“恢复可用知识网络”分开测试。

Controlled

规模可控

共 14,042 词、144,165 bytes。既能让全量上下文成为信息上限，又足以制造跨文档任务。

Connected

关系密集

正文有 131 处显式跨章引用，另有 Fourier–Hilbert–谱、概率–测度–积分等隐含长链。

Falsifiable

有条件陷阱

例如 L²/L¹ 包含关系、一致收敛与可导性，能测试 Graph 是否把有条件结论错误绝对化。

主比较与消融逻辑

比较可归因结论不能直接得出的结论
E vs B完整 WGEMemory 相对文件夹搜索的产品价值不能单独说明是 Wiki 还是 Graph 起作用。
E vs CTyped Graph 在 Wiki 已存在时的额外运行时价值不能说明 Graph 编译成本是否值得，需结合成本。
E vs D关系类型、方向、条件是否比普通链接更有用不能说明 Wiki 本身的价值。
E vs A编译压缩是否导致明显信息损失；复杂题是否有结构优势A 使用更多上下文，不作为成本公平的主胜负。
C vs BWiki 语义编译相对原文搜索的价值不能评估 Graph。

两条预算轨道

  • 信息上限轨道：A 使用完整语料；用于检查 E 是否因编译丢掉关键事实。报告实际 input tokens，不把 A 与 E 的成本混为一谈。
  • 成本标准化轨道：B–E 的最终 Context Pack/检索回填统一为 12k tokens（具体数值可在 pilot 后冻结），检索调用上限、总工具时间与输出上限一致。A 可另加一个确定性截断版本 A*，但不替代完整 A。
模型控制：回答模型、system prompt、答案格式、temperature、max output、工具接口和超时完全相同。编译模型可以不同，但必须记录；若 E 使用更强模型编译，必须另做“同模型编译”敏感性实验。

C01–C10 · 条件、反例与错误概括题

ID问题必须保留的边界
C01L² 是否总是 L¹ 的子集？不是；需底层测度空间条件，有限测度是常见充分条件。
C02一致收敛是否足以保证极限函数可导？不足；保持连续性，但可导需要导数序列等附加条件。
C03“紧致等价于闭且有界”在任意空间都成立吗？Heine–Borel 依赖有限维欧氏/有限维范数空间等背景。
C04每个连续函数都 Lebesgue 可积吗？取决于定义域与测度、函数是否绝对可积等。
C05每个 Cauchy 列都收敛吗？只在完备空间中保证。
C06所有五次方程都不能用根式求解吗？是一般五次无统一公式；特殊五次可能可解。
C07导数为零是否总能推出函数为常数？需要在连通区间/合适定义域上应用中值定理条件。
C08梯度为零是否足以保证局部最小？通常只是可微内点的一阶必要条件，不是充分条件。
C09Fourier 级数是否对所有函数都逐点收敛到原函数？收敛模式与正则条件必须区分。
C10连续双射一定是同胚吗？一般不；紧致到 Hausdorff 等条件下成立。

影响分析的金标

对每条纠正，人工预先标注三层影响集合，避免系统通过“全库重写”伪装高召回。

  • Direct：被纠正的 Claim、直接 Relation 和对应 Wiki 段落。
  • Dependent：消费该结论的 WikiModule、Graph 路径、测试问题。
  • Unaffected：语义相邻但不应改变的内容，用于测量过度重编译。
Impact Recall = 正确识别的 Direct + Dependent / 金标影响集合 Impact Precision = 正确识别的影响对象 / 系统声称受影响的对象 Over-recompile Rate = 被重编译但属于 Unaffected 的对象 / 全部重编译对象 Correction Recurrence = 纠错后仍输出被禁止旧断言的题数 / 相关回归题数
进化成立的最低语义：不是 Git 多了一个 commit，而是旧 Claim 的地位改变、依赖模块被正确更新、未受影响区域保持稳定，并且后续 Agent 行为使用了新状态。

07 / Protocol

可复现、盲评、先 pilot 再锁定主实验

flowchart TD P["预注册问题 假设 阈值"] --> F["冻结语料 Gold 与代码版本"] F --> I["20 题 Pilot 校准预算"] I --> K["锁定系统配置与 prompt"] K --> R["80 题 A-E 运行"] R --> B["匿名化与随机排序"] B --> J["双裁判盲评"] J --> H["分歧与硬失败人工仲裁"] H --> A["统计分析与消融结论"] A --> D["Go Narrow Pivot Stop"]

Step-by-step

  1. 预注册：冻结 H1–H5、主比较、80 题分类、rubric、硬失败、死亡阈值与排除规则。
  2. 冻结资产：记录 20 篇文件 hash、编译器 commit、模型版本、prompt 版本、索引参数和 Graph schema。
  3. 建立 Gold：两名标注者独立写 requiredClaims、requiredSources、expectedPath、conditions、forbiddenClaims；分歧仲裁后冻结。
  4. Pilot：按类别抽 20 题，仅用于修复实验基础设施、确定 12k 上下文预算和工具调用上限；不得用 Pilot 输出改写 Gold 答案。
  5. 系统构建：A–E 从同一 Corpus-v1 生成；Gold 完全隔离；为每组保存可审计 manifest。
  6. 运行：问题顺序随机；回答模型配置一致；temperature 建议 0 或最低稳定值；主实验每题每组一次，敏感性子集 20 题运行 3 个 seeds。
  7. 匿名化：移除系统名、路径风格和可能泄露组别的措辞；随机分配输出 ID。
  8. 评分：两个独立裁判先按 rubric 评分，再做成对偏好；裁判看 Gold，不看系统身份；硬失败和分差大于 1 的维度交给人工仲裁。
  9. 进化实验：按 T0–T4 顺序注入，不允许回看未来材料；每次固定知识快照并重跑指定题。
  10. 分析与决策：报告分布、置信区间、成本与失败类型；按门禁决定保留、降级或停止组件。

08 / Analysis

用配对分析回答“差异是否稳定”，不追逐单一平均分

主分析

  • 每道题在各组间天然配对。对 E–B、E–C、E–D 的 Task Utility 差值做 10,000 次题目级配对 bootstrap，报告均值差与 95% CI。
  • 按 D/H2/H3/C/G 分层报告；不允许单跳题数量稀释三跳和条件题的失败。
  • Pairwise Preference 用胜/平/负比例和 bootstrap CI；硬失败用配对二元差异或 McNemar/permutation 检验。
  • Relation/Impact precision-recall 同时报分子分母和具体错误边，避免小样本百分比误导。
  • 成本单独画 Pareto：任务质量 vs 每题在线 tokens/延迟；编译成本摊销为第 N 次任务后的累计成本。

建议报告的切片

切片要回答的问题
按 hop 数Graph 增益是否随路径长度增加，还是只增加噪音？
按条件敏感度类型化边是否减少绝对化，或反而放大错误边？
按显式/隐式链接系统是否只复制了原文的 131 处显式引用，还是能恢复有证据的隐含关系？
按时间点 T0–T4纠错后是否改善，改善是否依赖用户在当次 prompt 重新提醒？
按上下文预算6k/12k/24k 下，WGE 的结构优势何时出现或消失？
按错误来源失败来自编译、检索、Graph、pack 还是回答模型？
样本解释：80 题足以做架构取舍与错误分析，但不应把小差异包装成普遍科学结论。若 E–B 的 CI 跨过零或优势只来自少数题，应扩大真实 AI 学习题集，而不是调整阈值迎合结果。

门禁GoNarrow / PivotStop
SafetyE 的三类硬失败均不高于 B/C，且纠错后复发 ≤5%局部硬失败可定位并通过 Lint 修复无依据断言或冲突抹平显著增加；已纠正错误持续复发

Graph E vs C三跳以上 Path Completeness 提升 ≥15 个百分点；条件错误至少减少一半；单跳退化不超过 3 分只有影响分析有效，则 Graph 降级为离线依赖/Lint 层无稳定增益且引入更多无依据路径
EvolutionImpact precision/recall 均 ≥0.90；相关回归全部通过；过度重编译可控召回高但 precision 低，则优化依赖粒度只能全库重写仍漏改，或知识版本不一致
CompressionE 在 A 的事实质量附近，复杂题更好且在线上下文明显更少少量事实损失可通过 Evidence 回填修复单跳事实持续退化，说明编译损失不可接受
真正的产品死亡标准：如果 E 相对 B 不能减少重复解释、不能更好处理跨材料关系与条件、也不能让纠正进入后续行为，那么应停止“自治可演化知识层”的强产品叙事；保留有效的轻量组件，但不继续用 Graph、Wiki 或 Compiler 的复杂度为方向辩护。
10 / Report Template

最终报告必须允许读者复核，而不是只看冠军分数

一页结论应包含

  1. 语料、代码、模型、prompt、知识快照和问题集版本。
  2. H1–H5 每项是否通过，以及对应 CI、成本和硬失败。
  3. E vs B 的产品结论；E vs C/D 的 Graph 结论；不得混写。
  4. 按题类的胜负矩阵，特别标出 H3、C 与 Evolution。
  5. 五个最有代表性的成功案例与五个失败案例，附 Context Pack 和证据路径。
  6. 纠错注入前后 diff：旧 Claim、Relation、受影响 Wiki、回归题和最终答案。
  7. 下一步决策：Go、Narrow、Pivot 或 Stop，以及哪些产品承诺需要修改。

实验完成定义
