Normative Target Architecture Architecture 1.2

WikiMemory：通用 Agent 的可演化知识与长期记忆层

本文固定 WikiMemory 理想中应当是什么。它定义产品不变量、模块边界、数据与权限模型、Agent 接口和部署形态，不记录某次实验分数、当前对象数量或短期施工状态。当前实现差距见 实施状态，历史架构快照见 v3.3 归档。

01 / Constitution

架构存在的理由只有一个：让 Agent 随使用可靠地进步

WikiMemory 不是文件浏览器、摘要生成器，也不是把整张 Graph 倒进 Prompt 的检索外挂。它持续从人主动选择的材料，以及经权限合同提交的权威声明与纠正中形成问题假设、证据拓扑和可追溯、可版本化、可撤销的知识状态；部分问题在跨来源、跨时间更新中逐渐获得稳定身份，并在任务发生时只交付必要上下文。Agent 运行轨迹、工具日志、一般对话和任务结果不自动成为知识。

Evidence first

原文是证据根

Source 与 SourceSpan 不可变。Claim、Relation、Wiki 都是派生视图，随时可以丢弃并从证据重建。

Agent first

Context Pack 是产品输出

用户不维护 Wiki 或 Graph；Agent 通过稳定合同获得任务化知识、条件、冲突、缺口和引用。

Evolution first

变化必须影响未来行为

新材料或纠正只有在改变后续知识选择、回答或行动时才算完成，不以文件生成或对象数量代替。

Fail closed

不确定可以保存，不能静默污染

候选、争议、失效和隔离对象都可保留；默认消费只读取满足证据、状态、权限和审计版本的知识。

Graph capable

Graph 长期存在，在线条件触发

Graph 始终服务冲突、替代、影响传播和增量治理；在线候选导航按任务触发，遍历结果不自动进入 Prompt。

One contract

协议不能复制业务逻辑

MCP、HTTP API 与 CLI 都调用同一 Application Service；Transport 只负责协议、身份和序列化。

禁止架构漂移：单个 Dev 题、某次模型分数、当前 Graph 边数或短期 token 变化，不能直接改写本页不变量。架构变更必须来自新的产品约束、可靠事故证据、跨域重复结果或明确的人类决策，并留下 ADR。

对象权威性生命周期关键约束
Source / SourceSpan不可变证据根只追加；版本变化产生新对象内容 hash、来源 URI、loader 版本、精确定位
AssertedRecord主体对偏好/决策的证据可撤销、可替代principal、scope、authority basis；不能自动证明世界事实

Relation受审计关系候选、Canonical、隔离、失效端点、类型语义、条件、证据、审计版本全部闭合

Context Pack一次任务的临时投影按请求生成，不反向成为知识知识版本、scope、预算、选择理由、缺口与截断
双时态边界：MVP 必须回答“系统在某个 knowledgeVersion 当时记录了什么”，并保留明确来源版本的取代关系；现实世界任意 valid-time 区间推理是后续能力，不能仅凭字段存在就宣称完成。
加权证据拓扑：CURRENT 不是新的持久化真值轴，而是对 Canonical 证据拓扑的一次可解释投影：在给定知识版本、适用范围和任务下，综合 grounding、authority、currentness、applicability、关系支持、任务价值、不确定性与边际成本，呈现当前领先分支。权重允许先以序位和理由表达，不要求统一概率。新材料增加重新检查的优先级，但不自动淘汰旧分支。完整边界见 docs/specs/wikimemory-convergence-baseline-v1.md。
问题身份边界：人类选择材料构成注意力边界，AI 形成的是 QuestionHypothesis。问题文本只是投影；长期身份由 evidence basin、适用边界、更新语义和演化历史逐渐赢得。ACTIVE/CANONICAL 继续作为工程状态，不得等同身份成熟。
05 / Ingest & Compile

接收材料和学会材料是两个状态；发布与跨材料扫描也是两个可恢复阶段

stateDiagram-v2 [*] --> RECEIVED: ingest_material RECEIVED --> SOURCE_INGESTED: Loader + hash + SourceSpan SOURCE_INGESTED --> COMPILE_QUEUED: 创建 durable job COMPILE_QUEUED --> COMPILE_RUNNING: Worker 取得租约 COMPILE_RUNNING --> COMPILE_PARTIAL: 部分批次/关系阶段失败 COMPILE_RUNNING --> COMPILE_FAILED: 有界重试耗尽 COMPILE_RUNNING --> CLAIMS_PUBLISHED: Claim 门禁与原子发布通过 CLAIMS_PUBLISHED --> RELATION_SCAN_PENDING: 等待跨材料阶段 RELATION_SCAN_PENDING --> COMPLETED: Relation 门禁与索引 generation 完成 COMPILE_PARTIAL --> COMPILE_QUEUED: resume COMPILE_FAILED --> COMPILE_QUEUED: explicit retry COMPLETED --> COMPILE_QUEUED: recompile/new compiler version
  1. Loader 只机械规范化格式，输出统一 LoadedDocument；语义编译不感知 Markdown/PDF/HTML/TeX 细节。
  2. Worker 以输入 token 预算分批；每次模型调用立即记录 provider、prompt hash、usage、finish reason、重试和原始输出引用。
  3. Claim 和 Relation 分别通过结构门禁与语义门禁；失败对象进入物理 Quarantine，不进入默认索引。
  4. 单 Source publication 原子替换；跨 Source Relation 是独立阶段。后者失败保留 Claim 发布，并把状态标为 pending，而不是假报完成。
  5. 发布成功递增 Canonical generation；所有投影以 generation 绑定，陈旧索引必须重建或显式降级。

Seed

Graph 不能制造入口

先通过词法、别名和结构索引获得可靠 Seed。跨语言投影帮助召回，但永远不是回答证据。

Candidate graph

候选不是 Prompt

Graph 用于排序、冲突、依赖、替代和缺口发现；候选节点不会因为被遍历到就自动展示。

Visible context

完整单元竞争预算

Claim、条件、provenance 和全部必要 Evidence 作为不可拆原子；关系只有端点可见时才能进入。

Context Pack 至少返回：knowledgeVersion、scope、知识地图、选中 Claim/Wiki assertions、可见关系路径、SourceSpan、冲突、未知项、截断信息、选择 Trace ID 与序列化 token。它是 Agent 的输入合同，不是最终答案。

09 / Security & Authority

单用户 MVP 也必须携带 principal 与 scope，不能把“本地”当作无权限

身份与作用域

  • 每个请求都有 principalId；缺失时只允许 GLOBAL 读取。
  • PERSONAL 只属于本人；PROJECT 需要项目成员关系。
  • domain 只用于主题检索，不是权限边界。

工具能力

  • 只读、摄入、提议、提交、管理五类 capability 分离。
  • 写操作必须有幂等键、expectedKnowledgeVersion 和审计 actor。
  • 回滚、全局覆盖和高风险事实不能由普通查询会话静默执行。

数据边界

  • Quarantine、Gold、生产 Canonical 物理分离。
  • 容器镜像不包含 Benchmark、Stage B、运行日志和密钥。
  • 原始模型输出按保留策略保存引用，不默认返回 Agent。

供应链与网络

  • 模型 Provider 只接收明确编译批次；记录 provider/model/version。
  • 密钥只经 secret/env 注入，不写镜像与状态卷。
  • Loader 网络抓取与本地文件摄入分权；MVP 默认只接用户明确投递内容。

12 / Convergence Path

把已完成的工程内核变成阶段前提，再逐层收敛产品语义

门交付通过标准不做
