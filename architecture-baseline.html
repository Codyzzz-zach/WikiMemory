结构化 LintIssue（断点 7 修复）

// 14 个稳定 issueCode——不依赖文本匹配（linter:34-48） type IssueCode = | "MISSING_EVIDENCE" | "BROKEN_REFERENCE" | "EMPTY_STATEMENT" | "INVALID_PUBLICATION_STATE" | "BROKEN_RELATION_ENDPOINT" | "INVALID_RELATION_TYPE" | "RELATION_ENDPOINT_QUARANTINED" // 断点 1：端点被隔离则边不进图 | "SEMANTIC_SUPPORT_FAILED" | "SEMANTIC_ADDITION_MAJOR" | "SEMANTIC_INFERENCE_WRONG" | "SEMANTIC_LIMITS_MISSING" | "SEMANTIC_CITATION_FAILED" | "SEMANTIC_CONFLICT_DETECTED" // 断点 7：基于维度值而非文本匹配 | "SEMANTIC_WARNING"; interface LintIssue { code: IssueCode; severity: "error" | "warning" | "info"; affectedObject: string; detail: string; recommendedState: "CANONICAL" | "CANONICAL_DISPUTED" | "QUARANTINE"; }

冲突检测逻辑（linter:314-332）：verdict.support === "warning" || verdict.citation === "warning" → SEMANTIC_CONFLICT_DETECTED → recommendedState: "CANONICAL_DISPUTED"。不再用 issues.some(i => i.includes("冲突"))。

§08 / Compiler

编译层（未变）

compileSource()（compiler:52-183）三步：命题切分（LLM 返回 blockId+exactQuote）→ mapQuoteToSpan 映射 → Claim/Concept/Relation 编译。所有产出 publicationState=CANDIDATE（compiler:139-141），validity=SUPPORTED，lifecycle=ACTIVE。

Proposition 是中间产物，不持久化（决策 4A）。

§09 / Graph

Graph 层（断点 2+5+10 修复）

buildGraph（graph:105-136）：从 Canonical Claim/Relation 构建（不从 Wiki）。过滤 publicationState=CANONICAL && lifecycle=ACTIVE。不过滤 validity——validity 在 walkGraph/searchClaims 层面用消费矩阵处理。

walkGraph（graph:155-257）：BFS 从种子扩展。返回 { claims, relations, disputedClaims, unresolvedClaims }——后两者来自消费矩阵分类（graph:182-186 种子, graph:234-248 扩展节点）。方向检查在 graph:211-216。

searchClaims（graph:265-294）：简单包含匹配。过滤 getConsumptionRule(...).allowRetrieval（graph:276-280）——UNRESOLVED 和 DISPUTED 可搜到，CANDIDATE/QUARANTINED/SUPERSEDED 被排除。

§10 / Context Pack

Context Pack（断点 3 修复：Map-first）

buildContextPack（context-pack:174-315）10 步流程：

  1. 加载知识状态（context-pack:180-184）
  2. buildKnowledgeMap（context-pack:187）——检索前生成全局地图（topics/disputes/keyConcepts/recentChanges）
  3. buildGraph（context-pack:190）
  4. selectSeeds（context-pack:193-202）——map+keyword 双路种子（keyword-direct + map-topic）
  5. walkGraph 扩展（context-pack:205-209）——排除 RELATED_TO
  6. 预算控制 4chars≈1token（context-pack:211-256）
  7. 回填证据（context-pack:259）
  8. conflictsAndConditions 从 subgraph.disputedClaims 获取（context-pack:262-277）
  9. knownGaps 从 subgraph.unresolvedClaims 获取（context-pack:280-291）
  10. 裁剪 taskMap（context-pack:293-303）——地图是检索前生成的，Pack 携带裁剪版

wikiModules 为空（context-pack:309）——Phase 2 实现。
