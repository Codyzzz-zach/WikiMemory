# WikiMemory Convergence Baseline v1

> 状态：Accepted；2026-08-25 增补“问题假设与持续身份”语义
>
> 生效日期：2026-08-24
>
> 适用范围：产品方向、语义架构、后续迭代阶段与验收
>
> 权威级别：受《产品定义》和《用户故事》约束；用于取代旧迭代计划中仍然开放的路线与成功阈值

## 1. 为什么需要这份基线

WikiMemory 已经完成了大量底层机制和证明工作，但“每轮都做出成果、目标却继续后移”的过程没有形成稳定的阶段闭合。问题不是需要更快发布一个 Alpha，而是需要把以下三类内容分开：

1. 已经拿下、可以作为后续前提的确定性能力；
2. 仍然需要通过实现或实验学习的变量；
3. 只能由产品负责人改变的长期方向。

本基线把阶段闭合本身变成产品研发的一等约束。阶段可以以 `PASS`、`NARROW`、`REWORK`、`STOP` 或 `NO-GO` 结束；只要证据和边界完整，负结果也是完成，不会自动把目标向后移动。

## 2. 当前产品命题

WikiMemory 面向人类主动选择的知识材料，从中自动形成问题假设，并根据后续材料持续维护其证据、边界和身份；部分问题在跨来源、跨时间的更新中逐渐获得稳定的长期身份，并形成可追溯、可供 Agent 消费的 WikiModule。

人类提供的是注意力边界，而不是必须预先写出完整问题。AI 可以提出候选问题、匹配和生命周期建议，
但一次模型输出不能直接证明一个问题已经具有长期稳定身份。“稳定”首先指证据流域、适用边界、
更新语义和演化历史具有持续性，不要求规范问题文本永远不变。

它不是 Agent 全运行过程的自动记忆，也不把日志、轨迹或任务结果默认编译为知识。运行记录可以作为评测证据，但只有被人明确选择并作为材料提交后，才可能进入知识编译边界。

WikiModule 不承诺给出永远正确的唯一答案。它维护的是：

```text
QuestionState(Q, K, S, T)
  = 在知识版本 K、适用范围 S、任务语境 T 下，
    围绕长期问题 Q 的加权证据拓扑及其可解释投影
```

其中“当前认识”或 `CURRENT` 只表示在给定版本、范围和任务下，当前领先或证据支持更强的分支；不表示客观真理，也不永久淘汰其他分支。

## 3. 加权证据流

争议、条件、取代和未决不是彼此割裂的终局标签，而是信息在证据拓扑中的不同流动结果。新材料到达后，系统应能改变分支的权重、可见性、优先级和适用范围，同时保留这种变化的依据。

### 3.1 权重是向量，不是伪精确概率

概念上的权重向量可以包含：

```text
W = (
  grounding,          // 是否被可定位证据支撑
  authority,          // 来源与证据等级
  currentness,        // 时间和版本上的当前性
  applicability,      // 对条件、范围和对象是否适用
  relational_support, // 与其他 Claim 的支持、反驳、取代关系
  task_relevance,     // 对当前任务是否值得进入 Context Pack
  uncertainty,        // 未决、歧义和缺口
  marginal_cost       // 多花一次模型调用或上下文预算的边际价值
)
```

MVP 不要求把它们压缩成一个精确概率。可以先用可解释的序位、理由和有限枚举表达；但不得把“最新”“ACTIVE”或某个模型判断直接等同于真理。

新材料天然具有“值得重新检查”的当前性先验，但没有自动凌驾旧证据的权威。旧分支可以被降权、限域或变成历史领先分支，不能因新材料出现而静默删除。

### 3.2 与 MCTS 的关系

这里借用的是结构类比，而不是算法照搬：

- 逐步稳定的问题假设提供搜索边界；
- 证据和 Claim 形成可扩展分支；
- 新材料改变探索优先级和分支价值；
- Context Pack 是预算约束下的一次任务投影；
- 使用和评测结果可以改变下一轮实验优先级，但不会自动成为产品知识。

WikiMemory 当前不承诺真实访问计数、收敛概率、自博弈或最优策略证明。

## 4. 三层决策边界

### 4.1 硬不变量：必须确定

以下内容不交给模型自由决定：

- 每个产品断言必须落到可定位的 Canonical Claim 与来源证据；
- 原始证据、来源版本和 Claim 身份不可被静默改写；
- 条件、范围、时间和版本必须随 Claim 传播；
- 冲突分支和历史分支必须保留，不能被摘要抹平；
- 无证据内容不得进入产品知识；
- 构建必须可重放、项目必须隔离、派生产物必须可追溯；
- Context Pack 只能消费满足契约的 WikiModule 投影。

### 4.2 软语义：允许带不确定性

以下内容由证据、规则和模型共同估计，结果必须可解释、可修订：

- 哪个分支当前领先；
- 新问题假设与已有问题是复用、重叠、父子、分裂候选还是合并候选；
- 两个 Claim 是支持、争议、限域还是取代；
- 新材料应给现有分支增权、降权、分叉还是只补充条件；
- 在预算内，哪些内容对当前任务最有价值。

概念状态包括：`LEADING`、`CONDITIONAL`、`CONTESTED`、`UNRESOLVED`、`DEPRIORITIZED/HISTORICAL`。这些是产品语义，不等于当前持久化 schema 已经实现了相同字段。

### 4.3 人类决策：不能被实验自动重写

- North Star 和产品边界；
- 哪些材料被授权进入编译；
- 可接受的成本、风险和展示承诺；
- 阶段是否改变主变量或扩大范围。

实验发现默认进入 Discovery Backlog。只有显式决策才能改变当前阶段合同或 North Star。

## 5. 成本与效果的基本策略

成本优化不是统一压低 Token，而是先拿下确定性，再把模型预算用在真正的歧义上：

1. 哈希、版本、引用、身份、显式关系、条件传播和差分由确定性机制处理；
2. 只有关系判定、分支比较、信息缺口和任务价值等模糊问题调用模型；
3. 未变化的证据和已闭合判断复用，不重复推理；
4. 低价值歧义允许保持 `UNRESOLVED`，不为制造确定答案付费；
5. 验收同时观察质量、成本与不确定性保留，不用单一总分掩盖取舍。

因此后续阶段使用 Pareto/接受向量，而不是一个“越高越好”的综合分数。

## 6. 能力账本

| 层级 | 能力 | 2026-08-24 结论 |
|---|---|---|
| K0 | Evidence Kernel：材料、来源、Claim、引用、版本、可追溯性 | 已形成稳定基础 |
| K1 | Agent Runtime：构建、隔离、重放、审计、Context Pack 交付 | 已形成稳定基础 |
| K2-M | Question Identity Mechanism：QuestionFrame、形成门禁、生命周期、物化、恢复与消费链 | 机制已完成并通过 I2.5 验收 |
| K2-S | Question Identity Semantics：问题假设如何跨来源、跨时间赢得稳定身份 | 未证明；进入独立的 C1.5 阶段，不回写 I2.5 结论 |
| K3 | Weighted Semantic Flow：争议、条件、取代作为带权流动并可解释投影 | 未完成；当前核心缺口 |
| K4 | Budgeted Task Value：在成本约束下选择高价值信息 | 部分具备，尚未形成产品级策略 |
| K5 | Longitudinal Product Value：跨时间使用是否减少重复解释并改善任务 | 尚未证明，不在当前阶段偷跑 |

“已完成”表示可以作为阶段前提，不表示永不修改；修改它们必须由新阶段显式声明，而不能作为旁支顺手重构。

## 7. 收敛路线

### C0 — Convergence Baseline（本阶段）

- 主变量：是否能把产品命题、能力账本、硬不变量和阶段闭合规则固定下来；
- 输入：现有产品文档、Git 历史、I2/I2.5 证据与 I3-Sim 报告；
- 输出：本基线、ADR、同步后的权威文档；
- 非目标：改代码、设计最终权重算法、继续外部模型实验、启动真实用户 Pilot；
- 关闭条件：文档无相互矛盾的当前路线，Git 中存在可回退的闭合提交。

### C1 — Weighted Question State

- 只解决一个主变量：同一长期问题下，新旧证据如何形成可解释的领先、争议、限域、取代和未决分支；
- 优先复用 I3-Sim 冻结材料与已产生的模块/评审证据；
- 首先冻结阶段合同和最小表示，再决定是否改 schema 或编排器；
- 冻结输入 QuestionFrame 集合；问题创建、语义匹配、promotion、merge、split 和 archive 不得成为本阶段主动变量；
- 不同时扩展 loader、检索、UI、真实用户 Pilot 或新的知识来源。

### C1.5 — Question Hypothesis Persistence

- 只解决一个主变量：AI 提出的问题假设如何通过跨来源、跨时间证据获得复用、重叠、分裂、合并或长期稳定身份；
- 明确区分“当前可消费”与“长期身份成熟度”，不得用现有 `ACTIVE` 直接代表长期稳定；
- 先保存可解释、追加式的身份评估和软关系，在证据不足时保留竞争假设，不让一次模型输出直接执行不可解释的硬归并；
- 使用 C1 已形成的加权证据拓扑作为身份判断输入，避免退化为问题文本相似度；
- 在 C1 闭合前不启动实现、付费模型实验或修改 Question lifecycle。

### C2 — Budgeted Information Flow

- 只解决：在质量、成本和不确定性之间，如何为具体任务生成更有价值的 Context Pack；
- 比较确定性预筛、增量复用与歧义调用策略；
- 接受结果可以是某些歧义不值得继续消费 Token。

### C3 — Longitudinal Use

- 在 C1/C1.5/C2 机制稳定后，才验证跨时间、跨任务的真实产品价值；
- 指标和周期在阶段开始前根据真实使用设计，不沿用尚未证实的固定百分比；
- 目标是获得可解释的长期证据，不是为了满足发布日期而制造成功。

## 8. 阶段合同与闭合

每个阶段在任何实现或付费实验前，必须冻结以下字段：

| 字段 | 要回答的问题 |
|---|---|
| Stage Question | 本阶段唯一需要学习或证明什么？ |
| Primary Variable | 只能主动改变哪个核心变量？ |
| Input Slice | 使用哪些冻结材料、历史产物和场景？ |
| Acceptance Vector | 哪些质量、成本、不确定性和可解释性维度必须观察？ |
| Hard Invariants | 哪些已拿下能力不能回退？ |
| Cost Budget | Token、调用、人工审阅和时间上限是多少？ |
| Non-goals | 哪些诱人的问题本阶段明确不做？ |
| Stop Conditions | 何时停止继续加调用或补丁？ |
| Closure Artifact | 哪些报告、产物、决策和提交构成闭合？ |

允许的终局：

- `PASS`：证据支持按合同进入下一阶段；
- `NARROW`：保留有效部分，缩小命题后闭合；
- `REWORK`：主变量仍成立，但机制需要重做；
- `STOP`：边际价值不足，停止该方向；
- `NO-GO`：当前实现或命题不满足 Gate。

任何终局都不能自动启动下一阶段。新的执行必须有新的冻结合同。

## 9. 当前决议

1. I3-Sim 已以 `NO-GO` 闭合；它暴露了关系召回、条件表达和跨版本语义等缺口，不继续把同一 Gate 修补成成功；
2. 旧 I3 的“30 天 Pilot + 固定百分比”不是当前承诺，保留为历史设想；
3. C1 阶段合同已于 2026-08-25 接受；C1-A/B 与 C1-C Pure Shadow 已通过，C1-D 随后发现 18 份 Episode Sources 只有 12 份进入 7 个冻结 QuestionFrames，并按 Stop Condition 9.3 以 `REWORK` 闭合；0 provider calls / 0 tokens，未启动 C1-E；
4. 产品可以明确标注“争议/取代语义仍在完善”，但不能把当前机制描述成已经完成加权语义流。
5. I2.5 保持 `K2-M` 机制闭合；`K2-S` 是新识别并被产品负责人接受的语义未知。C1-D 已证明 Question association continuity 是真实加权状态闭包的硬前置；Question Association Bridge 或完整 C1.5 的顺序与范围必须由新合同显式决定，不以补丁自动启动。
