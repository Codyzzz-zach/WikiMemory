# Northstar API 弃用与资源回收规则

文件编号：NS-LCM-2026-01　发布机构：平台生命周期办公室　发布日期：2026-01-10　生效日期：2026-02-01

## API 弃用

任何已经向其他团队或外部客户开放的 API，在停止服务前必须至少提前一百八十个自然日发布弃用公告。公告需写明替代接口、迁移示例、停止接受新接入的日期和最终下线日期。仅在代码仓库中标记 deprecated 不算正式公告。若 API 存在已知安全漏洞，可以先关闭受攻击功能，但仍应在二十四小时内发布事件说明和迁移安排。

接口负责人每月需要检查调用方迁移进度。到下线日前仍存在调用量时，应联系调用方确认风险；这项沟通义务不自动延长一百八十日的公告期。一个 API 被弃用不等于承载它的整台服务器可以立即删除，相关日志和审计记录仍按各自规则保留。

## 非生产资源回收

测试或沙箱服务器连续九十天没有登录、部署和任务执行记录时，资源平台会将其标记为闲置。标记后先通知资源所有者并等待七天；所有者没有申请保留时，系统自动回收计算实例。数据库快照和对象存储不在本规则的自动删除范围内，它们必须遵循各自的数据保留政策。

## 发布回滚

生产发布单必须指定一个可部署的上一版本。监控触发回滚后，当班运维应在三十分钟内开始执行，而不是要求三十分钟内完成所有数据修复。是否需要数据回填由服务负责人另行判断。API 弃用期限、闲置资源回收和发布回滚是三个独立主题，不应互相推导。
