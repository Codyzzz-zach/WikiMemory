## 过程信号

### Graph 的真实增益

Graph 在以下题型中补到了 Seed 单独缺失的锚点：跨来源时间变化、跨材料事实连接、同概念的来源互证。例如 `B-T-HEALTH-003` 从 4/4 提升到 16，`B-K-DESIGN-004` 从 0/15 提升到 16。这说明 Relation 不是纯装饰。

### Graph 的真实风险

`B-K-DESIGN-011` 中，Graph 同时给出 WebAIM、W3C Claim 和 SUPPORTS 边，回答模型错误地把“两个 Claim 相互支持”升级成“两个独立规范来源”，得分从 B=12、P-seed=11 降到 P-graph=4。根因不是 WCAG 领域知识不足，而是 Context Pack 没有清楚表达来源角色与独立性边界。

### 确定性检索缺陷

`B-C-DESIGN-010` 查询只给出结构化编号 `2.5.7` 和中文问题。旧分词会把编号拆成单字符并全部丢弃，B / P-seed / P-graph 都得到空证据、得分 0。这类编号广泛存在于标准、法律、论文分节、软件版本和分类体系，是通用检索缺陷。

### 暂不修补的缺陷

`B-U-HIST-008` 用中文反事实问法表达“AI 已读完所有纸卷”，原文是英文且没有稳定词面重叠。B、Seed、Graph 均未召回。这里不能加入“纸卷→scroll”等题目词表，否则会把公开开发题写进系统；应在 Batch C 评估通用跨语言语义召回方案。

### Task Map 噪声

旧地图由全库高频词和 Concept 前 15 项生成，历史问题可能看到 `the/of/and` 和设计领域概念。这不是知识地图，而是与任务无关的上下文污染。

## 基于信号完成的通用修复（在线基线之后）

1. 稀疏检索和原始文件检索都保留完整 dotted identifier（如 `2.5.7`），并给结构化编号独立特征。
2. Loader → Source → manifest 机械保留 Markdown frontmatter metadata，供未来的 sourceRole、作者、发布者、版本、canonical URL 等 provenance 使用。
3. Context Pack 在出现 SUPPORTS 边时明确提示：语义支持不证明来源独立、同等权威或同为规范来源；并展示选中证据来源的 provenance。
4. Task Map 仍在 Seed 前生成，但只展示与当前查询有明确特征交集的主题、Concept、争议和变化，不再注入任意全库内容。

这些修复没有触发第二次在线回答，因此没有用同一批题优化在线分数。

## 下一判定点

Batch C 必须使用新领域、新来源簇并在系统接触 Gold 前冻结题目。只有在 Batch C 上同时满足以下三项，才可以扩大规模：

1. P-graph 相对 P-seed 的收益可复现，而不是只在少数公开题上偶然获益；
2. 每个新增正确答案的上下文和在线 token 成本合理；
3. 人工抽检 Claim、Relation、条件和来源归因忠实，且 Graph 不增加来源独立性、权威性或时间范围的硬失败。
