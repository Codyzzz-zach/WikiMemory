# E4a 六题 B/P smoke：首轮与 Span 解析修复后对照

状态：`DIRECTIONAL_ONLY`。这不是盲测，也不是人工双标 Gold；不能据此宣称产品已被证明有效。

## 实验合同

- 题目：Batch B 三个未参与早期开发的领域，每域 2 题，共 6 题。
- 组别：B（原 Markdown 稀疏检索）与 P（Canonical Claim + Graph + Evidence）。
- 公平性：同一回答模型、同一 judge 模型、temperature 0、12k 上下文预算、禁止联网。
- E-min：`BLOCKED_MISSING_GENERIC_WIKIMODULE_BUILDER`。没有用 requiredPoints/Gold 手工造 WikiModule。
- 回答过程不接触 requiredPoints、forbiddenClaims 或 Gold；这些字段只在盲化评分阶段出现。

## 最可信的因果信号不是单次总分，而是阶段漏斗

修复前，P 在 15 个必需证据锚点中只能召回 8 个；两个多来源问题分别只拿到单一来源，因此回答器合理地返回 insufficient，但产品任务仍失败。

根因是 Claim 的 evidenceSpanId 常采用 `span:...#chars-start-end`。检索器此前把完整片段 ID 直接查询基础 Span Map，导致：

1. 片段原文没有进入检索索引；
2. 片段对应的 sourceId 没有被解析；
3. Source URI/类型即使传入，也无法附着到 Claim；
4. 遥测只报告“传入了 Span 数组”，错误地显示 `usedEvidenceText=true`。

修复后：

- 67 个 Canonical Claim 证据引用成功解析，未解析数为 0；
- P 的必需证据召回从 8/15 提升到 14/15；
- 完整覆盖问题从 3/6 提升到 5/6；
- P 的两个 insufficient 硬失败消失；
- P 的平均答案分从 8.667 提升到 15.333。

这条链路满足“中间机制改善 → 上下文改善 → 答案改善”，比只看最终分数更能支持修复有效。

## 仍不能下的结论

1. 不能说 P 已经稳定优于 B。B 的输入检索没有变化，但两轮分数从 13.167 漂到 11，说明回答/评分仍有随机波动。
2. 不能说 Graph 贡献了全部增益。当前改善首先来自 Evidence 与 Source 元数据真正进入稀疏检索；需要独立消融 Seed-only 与 Seed+Graph 才能拆分 Graph 贡献。
3. 不能扩写为“跨领域已验证”。这里只覆盖 3 个公开验证领域、6 个问题。
4. 不能解锁 E-min。通用 WikiModule builder 尚不存在。

## 剩余缺口与下一轮门槛

- 唯一未召回锚点是历史题中的论文方法事实：中文“论文”无法命中英文 URI 中的 `paper`。不能用领域或中英词表硬编码修复；需要通用的跨语言语义检索/查询规划层。
- 下一轮先做 3 次重复的 6 题 B/P 运行，报告均值、方差、逐题一致性和 hard-failure 并集；若结论不稳定，不扩到 32 题。
- 增加 Seed-only vs Seed+Graph 消融，确认 Relation 是否真的增加覆盖，还是只增加上下文噪声。
- 只有上述门槛稳定后，才设计 Gold 隔离的通用 WikiModule builder 与 E-min。
