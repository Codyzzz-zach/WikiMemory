# E4 Smoke：Seed-only 与 Seed+Graph 消融分析

日期：2026-07-28  
性质：公开 Batch B 上的方向性实验，不是盲测产品结论，也不是人工 Gold 验收。

## 1. 本轮要回答的问题

在回答模型、题目、运行次数和编译快照保持一致时，Graph 扩展相对仅使用检索种子 Claim：

1. 是否补回更多题目要求的证据；
2. 是否提高回答质量；
3. 是否引入上下文成本、噪声或硬失败；
4. 当前证据是否足以决定扩大到完整 32 题或修改 Graph 架构。

实验模式为：

- `B`：原始 Markdown 文件夹检索；
- `P-seed`：Canonical Claim 检索，不做 Graph 扩展；
- `P-graph`：相同 Claim 种子加受审计 Relation 的 Graph 扩展。

`P-seed` 与 `P-graph` 使用同一冻结知识快照。题目 Gold、required points 和期望证据不进入检索或回答提示词；它们只供离线覆盖检查和盲裁判使用。

## 2. 离线上下文组成

| 模式 | 完整覆盖题目 | 找到的要求证据 | 平均上下文 token | 相对 P-seed |
|---|---:|---:|---:|---:|
| B | 4/6 | 11/15 | 468 | -59.9% |
| P-seed | 5/6 | 14/15 | 1166 | 基线 |
| P-graph | 5/6 | 14/15 | 2430.17 | +108.4% |

在当前 6 题上，Graph 没有新增 required-evidence 锚点，但把平均上下文从约 1166 token 增至 2430 token。因而如果 Graph 有价值，价值来自补充关系路径、跨来源语义组织或辅助解释，而不是当前离线锚点指标中的额外召回。

## 4. 过程信号驱动的领域无关修复

### 4.1 显式时间范围门禁

健康演化题明确要求 2020-03 到 2020-07，但原上下文混入 2020-10 Claim。问题不是健康领域知识不足，而是检索缺少通用时间范围约束。

本轮增加了领域无关的显式时间过滤：

- 仅当查询中能解析出至少两个年月边界时启用；
- 没有精确年月的 Claim 保留，避免误删背景知识；
- Claim 中所有精确年月都落在闭区间外时才排除；
- 支持数字、中文和英文日期；
- 避免把来源编号（如 `2024-003`）误判为月份。

修复后，2020-10 Claim 同时从 `P-seed` 和 `P-graph` 中移除。定向三次复测两组均为 13/16、标准差 0、硬失败 0。这个结果说明时间噪声被清除，但没有证据证明 Graph 对该题有额外价值。

定向留痕：[`时间范围复测 v2 报告`](./runs/e4-graph-ablation-2026-07-28T05-07-06-494Z/rescore-v2/score-report.json)。

### 4.2 裁判合同修复

第一版模型裁判出现了可复现的内部矛盾：rationale 明确认可答案覆盖要求，却仍机械地给多个维度 2/4；同时它在看不到上下文时，以“Claim ID 不在 Gold 中”为由扣分。这是测量工具缺陷，不能作为产品失败信号。

v2 做了两项修复：

- 为 0–4 每一档提供独立评分锚点，并要求理由和分数一致；
- 在裁判前确定性检查引用 ID 是否真实存在于该匿名样本的上下文中，裁判只收到有效/无效计数，不接触模式身份。

仍需保留限制：同模型裁判不是人工 Gold；引用预检只验证“标识符存在”，不验证“引用是否真正蕴含答案”。因此当前分数只能用于方向性比较，不能宣传为产品准确率。

## 5. 第一性结论

1. **Graph 不是当前 6 题的普遍增益器。** 两题明显获益，三题持平，一题退化；逐题差值中位数为 0。
2. **Graph 有局部结构价值。** 历史跨来源综合题的增益与 Graph 补入论文、仓库及来源角色路径相符，不只是锚点召回数量变化。
3. **Graph 成本当前偏高。** 平均上下文增加 108.4%，且设计题显示无关边可能改变回答稳定性。
4. **硬安全没有退化。** 两种模式 36 个回答均无硬失败，但样本量仍小。
5. **不能据此针对三类公开材料调参。** 这会把公共 Batch B 变成训练集，制造欺骗性 reward，并伤害多领域泛化。

## 6. 架构裁决与下一阶段门槛

本轮不删除 Graph，也不宣称 Graph 已经证明能提高通用 Agent 效果；保留它作为受审计、可开关、可测量的上下文组织层。

现在不应仅为了提高这 6 道公开题的均分而建立题型路由或领域词表。也不应直接把完整 32 题结果当确认性证据，因为 Batch B 已参与诊断。

下一阶段应建设新的盲持出集 Batch C：

- 使用此前未参与修复的来源簇和领域；
- 同时包含单文档事实、条件保真、时间演化、冲突/纠错、跨来源综合；
- 预先冻结题目、证据和评分合同，再运行 `B / P-seed / P-graph`；
- 主指标为逐题配对差值及其分布，不只看总均分；
- 同时报告证据覆盖、上下文 token、硬失败、引用存在性和人工抽检；
- 在小型 canary 上迭代，只有门禁通过才扩到完整持出集。

扩大到 32 题的条件不是“本轮均分好看”，而是：新盲域上 Graph 增益可复现、代价可接受、硬失败不增加，并且人工抽检确认增益来自忠实知识组织而非裁判偏差。

E-min 仍保持阻断：当前没有 Gold-independent 的通用 WikiModule 生产与审计链，禁止根据测试题手写模块。
